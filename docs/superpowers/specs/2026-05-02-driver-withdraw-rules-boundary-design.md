# 花小猪司机端提现规则边界规格书

## 1. 概述与适用范围

**文档目的：** 定义花小猪司机端提现全链路的产品规则与边界条件，供开发与测试对齐预期行为。

**适用范围：**
- 司机端 APP 提现功能
- 银行卡绑定/更换
- 钱包余额查询与冻结规则
- 提现申请与记录查询

**参考依据：**
- 现有设计文档 `2026-04-29-driver-withdraw-product-rules-design.md`
- 代码实现 `srvDriver/internal/service/walletService.go`
- 数据模型 `srvDriver/internal/model/wallet.go`、`enum_wallet.go`

| 规则项 | 限制值 | 说明 |

| 银行卡号最大长度 | 20 字符 | 超长拒绝绑定 |

| 认证类型 | 状态要求 | 对提现影响 |

## 3. 前置资质规则详解

### 3.1 实名认证状态枚举

| 状态码 | 状态名 | 是否可提现 | 说明 |
|--------|--------|------------|------|
| 0 | 未认证 | ❌ | 未提交实名资料 |
| 1 | 认证中 | ❌ | 已提交，等待审核 |
| 2 | 已认证 | ✅ | 审核通过 |
| 3 | 认证失败 | ❌ | 审核驳回，需重新提交 |

### 3.2 实名认证对提现的影响

**规则：** 仅 `status=2`（已认证）允许发起提现。

**校验顺序：**
1. 查询 `driver_realname` 表该司机记录
2. 若记录不存在 → 返回禁提原因 `VERIFY_PENDING`
3. 若 `status ≠ 2` → 返回禁提原因 `VERIFY_PENDING`

**边界场景：**

| 场景 | 预期行为 |
|------|----------|
| 从未提交实名资料 | 提现页显示"需完成实名认证"，按钮禁用 |
| 实名审核中 | 提现页显示"认证审核中"，按钮禁用 |
| 实名审核驳回 | 提现页显示"认证未通过，请重新提交"，按钮禁用 |
| 实名已过期（expire_date < 当前日期） | 当前未校验，后续可扩展 |

### 3.3 驾驶证/车辆认证

**当前规则：** 不作为提现前置条件，仅影响接单资格。

**扩展预留：** 后续可增加驾驶证过期、车辆年检过期等风控规则。

## 4. 银行卡绑定规则详解

### 4.1 银行卡状态枚举

| 状态码 | 状态名 | 说明 |
|--------|--------|------|
| 1 | 有效 | 当前绑定中，可用于提现 |
| 2 | 已解绑 | 历史记录，不可使用 |

### 4.2 绑定规则

**单卡限制：** 每个司机仅能绑定 1 张有效银行卡。

**绑定校验顺序：**
1. 检查是否已存在有效银行卡（`driver_bank_card` 表，`status=1`）
2. 若已存在 → 返回错误 `ErrBankCardAlreadyBound`
3. 校验银行卡号长度 ≤ 20 字符
4. 校验必填字段：银行名称、银行卡号、持卡人姓名
5. 创建绑定记录

**必填字段：**

| 字段 | 说明 |
|------|------|
| bank_name | 银行名称（如"工商银行"） |
| bank_code | 银行代码（如"ICBC"） |
| bank_card_no | 银行卡号（脱敏存储，如 ****8821） |
| bank_card_no_encrypt | 银行卡号（AES加密，用于打款） |
| account_name | 持卡人姓名 |
| card_type | 卡类型：1-借记卡，2-信用卡 |

### 4.3 更换规则

**频次限制：** 滚动周期 30 天内只能更换 1 次（距上次修改需满 30 天）。

**更换校验顺序：**
1. 查询当前绑定卡及 `last_modified_at` 时间
2. 计算 `next_available = last_modified_at + 30天`
3. 若 `当前时间 < next_available` → 返回错误 `ErrBankCardChangeLimit`，附带下次可换时间
4. 更新银行卡信息，重置 `last_modified_at = 当前时间`

**边界场景：**

| 场景 | 预期行为 |
|------|----------|
| 首次绑卡 | 允许，无频次限制 |
| 9月10日换卡，9月20日再次换卡 | 拒绝，提示"下次可换卡时间: 10月10日" |
| 9月10日换卡，10月10日换卡 | 允许（满30天） |

### 4.4 银行卡对提现的影响

| 场景 | 提现页行为 |
|------|------------|
| 未绑定银行卡 | 显示"请先绑定银行卡"，按钮禁用，返回 `NO_BANK_CARD` |
| 已绑定有效卡 | 显示银行卡摘要（银行名 + 脱敏卡号），允许提现 |

## 5. 提现申请规则详解

### 5.1 提现资格校验顺序

服务端按以下顺序依次校验，**任一不通过立即返回对应错误**：

| 序号 | 校验项 | 失败错误码/原因码 | 失败文案 |
|------|--------|-------------------|----------|
| 1 | 司机 ID 合法（>0） | `ErrInvalidDriverID` | 司机ID非法 |
| 2 | 实名认证已通过 | `VERIFY_PENDING` | 需完成实名认证 |
| 3 | 已绑定银行卡 | `NO_BANK_CARD` | 请先绑定银行卡 |
| 4 | 今日提现次数 < 3 | `WITHDRAW_COUNT_LIMIT` | 今日提现次数已达上限(3次) |
| 5 | 可提现金额 > 0 | `AVAILABLE_AMOUNT_ZERO` | 可提现余额为零 |
| 6 | 提现金额 ≥ 1 元 | `ErrWithdrawMinAmount` | 提现金额低于最低限额 |
| 7 | 提现金额 ≤ 5000 元 | `ErrWithdrawAmountLimit` | 提现金额超限 |
| 8 | 提现金额 ≤ 可提现金额 | `ErrInsufficientBalance` | 可提现余额不足 |
| 9 | 冻结金额限制 | `ErrFrozenAmountLimit` | 部分金额冻结中 |

### 5.2 金额校验规则

**口径定义：**
```
可提现金额 = balance - frozen_amount
```

**校验逻辑：**
```
若 amount < 1 → 拒绝
若 amount > 5000 → 拒绝
若 amount > (balance - frozen_amount) → 拒绝
若 frozen_amount > 0 且 (balance - frozen_amount) < amount → 拒绝
```

**边界值测试用例：**

| 测试场景 | 输入金额 | 余额 | 冻结金额 | 预期结果 |
|----------|----------|------|----------|----------|
| 刚好最低限额 | 1.00 | 100 | 0 | ✅ 成功 |
| 刚好最高限额 | 5000.00 | 6000 | 0 | ✅ 成功 |
| 低于最低限额 | 0.99 | 100 | 0 | ❌ ErrWithdrawMinAmount |
| 高于最高限额 | 5000.01 | 6000 | 0 | ❌ ErrWithdrawAmountLimit |
| 余额刚好够 | 100.00 | 100 | 0 | ✅ 成功 |
| 余额不足 | 100.01 | 100 | 0 | ❌ ErrInsufficientBalance |
| 有冻结金额-够提 | 50.00 | 100 | 50 | ✅ 成功 |
| 有冻结金额-不够提 | 60.00 | 100 | 50 | ❌ ErrFrozenAmountLimit |
| 全额冻结 | 1.00 | 100 | 100 | ❌ AVAILABLE_AMOUNT_ZERO |

### 5.3 每日次数限制

**规则：** 自然日内（00:00-23:59）最多提现 3 次。

**计数方式：** 统计 `driver_withdraw_record` 表当日创建的记录数（不限状态）。

**边界场景：**

| 场景 | 预期行为 |
|------|----------|
| 今日第 1 次提现 | ✅ 允许 |
| 今日第 2 次提现 | ✅ 允许 |
| 今日第 3 次提现 | ✅ 允许 |
| 今日第 4 次提现 | ❌ 拒绝，返回 WITHDRAW_COUNT_LIMIT |
| 跨日重置 | 次日 00:00 计数清零，重新允许 |

### 5.4 提现单号生成规则

**格式：** `WD` + `yyyyMMddHHmmss` + `司机ID后4位`

**示例：** 司机ID=12345，2026-05-02 14:30:15 提现
```
WD20260502143015345
```

## 6. 钱包余额与冻结规则详解

### 6.1 钱包数据结构

| 字段 | 类型 | 说明 |
|------|------|------|
| balance | float64 | 当前可用余额（可提现部分） |
| frozen_amount | float64 | 冻结金额（T-3 结算中不可提现） |
| total_income | float64 | 累计总收入 |
| total_withdraw | float64 | 累计提现金额 |
| version | int | 乐观锁版本号 |

### 6.2 冻结金额规则

**冻结场景：** T-3 结算机制——订单完成后资金冻结 3 天，第 4 天解冻可提现。

**当前实现：** `frozen_amount` 字段存储冻结总额，不拆分明细。

**可提现金额计算：**
```
available_withdraw_amount = balance - frozen_amount
```

**边界场景：**

| 场景 | balance | frozen_amount | 可提现金额 |
|------|---------|---------------|------------|
| 无冻结 | 500 | 0 | 500 |
| 部分冻结 | 500 | 200 | 300 |
| 全额冻结 | 500 | 500 | 0 |
| 冻结超余额（异常） | 300 | 500 | 0（按 min 计） |

### 6.3 余额变更场景

| 场景 | balance 变化 | frozen_amount 变化 | 说明 |
|------|--------------|-------------------|------|
| 订单收入 | +金额 | 不变 | 订单结算入账 |
| 提现申请 | -金额 | 不变 | 扣减可提现余额 |
| 提现失败回退 | +金额 | 不变 | 余额回补 |
| 奖励发放 | +金额 | 不变 | 活动奖励入账 |
| 罚款扣款 | -金额 | 不变 | 违规罚款 |

### 6.4 并发扣款保护

**机制：** 乐观锁（version 字段）

**流程：**
1. 读取钱包记录，获取当前 version
2. 更新时带条件 `WHERE version = 当前version`
3. 若 affected_rows = 0 → 版本冲突，返回错误要求重试

**错误码：** `ErrUpdateBalance`（余额更新失败）

### 6.5 钱包流水记录

每次余额变更写入 `wallet_transaction_log` 表：

| 字段 | 说明 |
|------|------|
| transaction_no | 流水号 |
| transaction_type | 交易类型：1-订单收入 2-奖励 3-提现 4-罚款 5-退款 |
| amount | 交易金额 |
| balance_before | 交易前余额 |
| balance_after | 交易后余额 |
| frozen_before | 交易前冻结金额 |
| frozen_after | 交易后冻结金额 |
| related_id | 关联ID（订单ID/提现ID） |
| status | 状态：1-成功 2-失败 3-处理中 |

## 7. 状态流转与异常处理

### 7.1 提现记录状态流转

```
┌─────────────┐
│   申请提现   │
└──────┬──────┘
       │ 校验通过
       ▼
┌─────────────┐
│  处理中(1)  │──────────────┐
└──────┬──────┘              │
       │                     │
       │ 异步打款             │ 超时/渠道失败
       ▼                     ▼
┌─────────────┐       ┌─────────────┐
│   成功(2)   │       │   失败(3)   │
└─────────────┘       └──────┬──────┘
                             │
                             │ 余额回退
                             ▼
                      ┌─────────────┐
                      │ 余额已回补   │
                      └─────────────┘
```

### 7.2 各状态说明

| 状态码 | 状态名 | 前端展示 | 后续操作 |
|--------|--------|----------|----------|
| 1 | 处理中 | "处理中，预计2小时到账" | 等待异步回调 |
| 2 | 成功 | "已到账" | 无 |
| 3 | 失败 | "提现失败：{fail_reason}" | 可重新发起提现 |

### 7.3 提现失败处理

**失败触发条件：**
- 打款渠道返回失败
- 银行卡已注销/冻结
- 系统超时

**失败处理流程：**
1. 更新提现记录状态为 `3`（失败）
2. 记录失败原因到 `fail_reason` 字段
3. 回补钱包余额：`balance += amount`
4. 写入钱包流水（类型：退款）
5. 更新 `finish_time`

**失败原因枚举（预留）：**

| 原因码 | 文案 |
|--------|------|
| BANK_CARD_INVALID | 银行卡无效或已冻结 |
| CHANNEL_ERROR | 支付渠道异常 |
| SYSTEM_TIMEOUT | 系统超时，请重试 |
| RISK_REJECT | 风控拒绝 |

### 7.4 事务一致性保证

**提现申请事务：**
```
BEGIN TRANSACTION
  1. 创建提现记录（status=1）
  2. 扣减钱包余额（乐观锁）
  3. 写入钱包流水
COMMIT
```

**失败回退事务：**
```
BEGIN TRANSACTION
  1. 更新提现记录状态为失败
  2. 回补钱包余额（乐观锁）
  3. 写入退款流水
COMMIT
```

### 7.5 异常场景处理

| 异常场景 | 处理方式 | 用户感知 |
|----------|----------|----------|
| 余额扣减失败（乐观锁冲突） | 事务回滚，返回错误 | "系统繁忙，请重试" |
| 提现记录创建失败 | 事务回滚 | "创建记录失败" |
| 异步打款超时 | 状态保持"处理中"，等待人工介入 | 显示"处理中" |
| 部分打款成功 | 当前不支持，按失败处理 | 回退全部金额 |
