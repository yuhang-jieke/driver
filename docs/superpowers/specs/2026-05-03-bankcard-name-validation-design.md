# 银行卡持卡人姓名验证设计文档

**日期**：2026-05-03  
**功能**：银行卡绑定时持卡人姓名格式验证（2-6个汉字）

## 需求概述

在银行卡绑定和更换流程中，对持卡人姓名字段进行格式验证，确保输入为2-6个汉字。采用前后端双重验证策略，既保证用户体验，又确保数据安全。

## 验证规则

### 正则表达式

```
^[一-龥]{2,6}$
```

**规则说明**：
- `一-龥`：匹配所有常用汉字（基本汉字Unicode范围）
- `{2,6}`：长度限制为2到6个字符
- `^` 和 `$`：确保整个字符串匹配，不允许前后有其他字符

**有效示例**：
- ✅ "张三"（2个汉字）
- ✅ "欧阳修"（3个汉字）
- ✅ "爱新觉罗启星"（6个汉字）

**无效示例**：
- ❌ "张"（1个汉字，少于2个）
- ❌ "爱新觉罗启星明"（7个汉字，超过6个）
- ❌ "Zhang San"（包含英文字母）
- ❌ "张三123"（包含数字）
- ❌ "张 三"（包含空格）

## 前端实现

### 实现位置

`driverfrontend/src/app/` 中的银行卡绑定表单组件（需要创建或定位现有组件）

### 验证时机

1. **实时验证**：用户输入时进行验证
2. **失焦验证**：输入框失去焦点时验证
3. **提交验证**：表单提交前最终验证

### 实现方式

```typescript
// 验证函数
function validateAccountName(name: string): boolean {
  const regex = /^[一-龥]{2,6}$/;
  return regex.test(name);
}

// 错误提示文案
const ERROR_MESSAGE = "持卡人姓名必须为2-6个汉字";
```

### 用户体验

- 输入时实时显示验证状态（红色边框/错误提示）
- 验证失败时禁用提交按钮
- 错误提示清晰友好，告知用户正确格式

if !isValidChineseName(req.AccountName) {

// 辅助函数（添加到文件末尾）
func isValidChineseName(name string) bool {
    // Go正则表达式使用 \x{} 语法表示Unicode
    matched, _ := regexp.MatchString(`^[\x{4e00}-\x{9fa5}]{2,6}$`, name)
    return matched
}

## 安全考虑

### 为什么需要后端验证

即使前端已经验证，后端仍需验证的原因：

1. **防止绕过**：恶意用户可以绕过前端验证直接调用API
2. **数据一致性**：确保数据库中的数据符合业务规则
3. **纵深防御**：金融应用的安全最佳实践

### 验证位置选择

在实名认证姓名一致性校验**之前**进行格式验证：
- 先验证格式，快速失败，减少不必要的数据库查询
- 格式验证是更基础的规则，应该先执行

## 注意事项

1. **Unicode范围**：`一-龥` 覆盖了常用汉字，但不包括生僻字。如果需要支持生僻字，可能需要扩展Unicode范围。
2. **Go正则语法**：Go中使用 `\x{4e00}` 而不是 `一` 来表示Unicode字符。
3. **错误码分配**：需要确认 `40015` 是否已被使用，如有冲突需调整。
4. **前端组件定位**：需要先确认银行卡绑定表单组件是否已存在，如不存在需要创建。
